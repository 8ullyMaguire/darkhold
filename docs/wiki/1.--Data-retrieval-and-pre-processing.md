## Data retrieval

The [archive of our own](https://archiveofourown.org/tags/Marvel/works) website collects fanworks written by people around the world that are all related to a given topic. The data you'll want to obtain from the website for this project includes the id of each written work, the author name, the title of the work, published and updated dates, the number of chapters and the number of words. You will also want different popularity metrics such as the total number of hits, likes (named kudos on this website), comments and bookmarks which will be used in the non-personalized recommender. Each fanwork is also tagged in different ways by the authors containing tags regarding the characters that appear in the work, the relationships between different characters and a series of additional tags that are descriptive of the work. These tags will be used in the content-based approaches and should also be saved. Finally, for each work, a list of identified users which gave a like to the work can be downloaded and used as evidence that the user likes the work. While other evidence could have been downloaded for registered users such as whether they had given comments or they had bookmarked the work this was not done due to time constrains.

To download all the needed data I wrote the AO3_scrapper.py program. It is a script that will take a main link to a list of works and then it will iterate through the different pages to download the metadata for each fic. The website itself contains already a series of filters which allow the user to narrow down their search. If the link provided to the scrapper already contains such filters the search will be limited to the works that fulfill those filters. Note that the list of fics is not static, it is updated whenever someone publishes either a new work or a new chapter of an existing work, therefore, if you are running the scrapper for several days there will be duplicated entries which you will want to remove before doing anything with the data. Note also that there is a five second delay encoded in the script after downloading a page. This was done by request of the archive managers and should not be touched.

To execute the scrapper just run the following script:

`python3 ./1_scrapper/AO3_metadata_scrapper.py -l LINK -o NAME_FOLDER `

Where LINK is the link to the main works website that you wish to download. Note than when filters are applied and the link is complex the name of the link should be placed between "". NAME_FOLDER is the name of the folder where the results will be printed. Additional options of the script include:
* -c which indicates the page number you want it to start from in case the script stopped due to a time out. 
* --download_comments: This option is not activated by default due to the amount of time needed to download this data. The way the archive is structured there are a set of comments per page and a fic can have hundreds of comments and as such hundreds of pages that will need to be downloaded one by one.
* --base_html: This is the base link to the archive. No need to change it unless the archive changes locations.

The output coming from this script is a folder, with the name provided in the -o option. In there is a second folder called metadata where a set of files will be found, each belonging to the metadata extracted for one of the work pages and containing 20 works. If comments were downloaded they will occupy a second folder.

## Pre-processing

To make the information downloaded ready for use in the recommender programs some pre-processing is needed. The first thing that needs to be done is to put all the information in a single file. As each file contains the header and we do not need to include that line we can do the following:

`cat * | grep -v "idName" >metadata.raw.txt`

This needs to be executed inside the metadata folder. 

Now the metadata.raw.txt needs to be cleaned and formated in different ways. All the necessary steps are included in the script ./1_scrapper/clean_retrieved_data.py.

1. Clean raw metadata to obtain a clean dataset. This includes: deleting duplicated entries, deleting '"' from titles, fill empty fields with - which will be the missing data value, delete the colon found in some numbers, and lastly remove the spaces in the fields containing tags. This last is done because when working with this kind of metadata we want each tag to be considered as a unity and not a group of different words. To clean the data:

`python3 ./1_scrapper/clean_retrieved_data.py -i metadata.raw.txt -o metadata_fics.clean.txt --clean_metadata`

2. The second step consists in obtaining the user to item table. This is the main input file for many of the recommenders included here and it consists in a three column table where the first column contains the name of the user, the second the id of the work and the third the rating. I take the id of the work instead of the title because the id is unique unlike what could happend with the title. Users, as they are only registered users, will be unique too. Ratings in this case are simply 1, as we do not have more information about how much a user likes a certain work. To obtain this table:

`python3 ./1_scrapper/clean_retrieved_data.py -i metadata_fics.clean.txt -o user2item.txt --obtain_user_item_file`

Note that the options --min_num_reads and --min_num_liked allow you to set a requirement about the amount of works a user needs to have liked in order to be included (--min_num_liked) and the minimum amount of times a work needs to have been liked (--min_num_reads) in order to be included in the dataset. This allows you to discard users and items for which little information is available to avoid cold start problems.

3. Finally the dataset will be split into three: training, validation and test. As there's no information on when each user read and liked a work, the script will create the three subsets by randomly masking user to item interactions. The splitting will also be made in such a way that each user and each item appear at least once in the three sets. This is done because in collaborative filtering a relation between user and item cannot be predicted if either of them is absent. As the training is often a time consuming process I will only take a subset of the data. This can be done by either taking the N users with the largest amount of information or by taking a random set of N users. Note that even if N users are selected, the filtering done to ensure that all three parts have all users and all items may decrease the final amount of users and their corresponding items.

`python3 ./1_scrapper/clean_retrieved_data.py -i user2item.txt --split_data --tag Best --num_users 10000 --outTrain train.u2i.txt --outVal val.u2i.txt --outTest test.u2i.txt`

The input file here is the file obtained at point 2. The tag indicates that it will keep the users with the largest amount of information, alternativelly it could use the tag Random which would select a random subset of users. The num_users indicates the amount of users it will start with. There will be three different out files which are determined with --outTrain, --outVal and --outTest. The percentages of data that will be allocated to each group are 70%, 15% and 15%.

4. (Optional) There is also the possibility to recommend authors instead of items. The advantage of recommending authors is that the rating can be scaled up by dividing the number of works by a given author a user has read, giving a more solid idea on the preference between user and author. To get this file and split it into training, validation and test you need to:

`python3 ./1_scrapper/clean_retrieved_data.py -i metadata_fics.clean.txt -o user2author.txt --obtain_user_authors_file`

Note that in this case the ratings are calculated by dividing the number of works a user has read from an author by the total of works written by the author. This is normalized to a scale that goes from 1 to 5, so that when a user has read at least one work of the author the minimal rating will always be 1 and if they have read all the works it will be 5. Note also that most of the programs included here assume that the relation between user and item is binary and will reduce this information despite the inclusion of different ratings.

Now to split the data:

`python3 ./1_scrapper/clean_retrieved_data.py -i user2author.txt --split_data --tag Best --num_users 10000 --outTrain train.u2a.txt --outVal val.u2a.txt --outTest test.u2a.txt`

## Test dataset

All scripts included here were tested on a dataset obtained and pre-processed by the tools explained above. During June 2020, I performed three runs of the scrapper, with different filters set for the number of words. This was done because the archive is designed in such a way that at most 5000 pages can be accessed, which means 100,000 works can be retrieved. Older works can be accessed through the use of filters. As the Marvel collection is more extensive I decided to focus on longer works and discard fanworks of less than 2,000 words. I collected metadata for a total of 183,270 works that had been read by 531,246 users. 

As expected the data is very sparse, few works have been read by a lot of users and also few users have read a lot of works. Note that the likes with which we are working with represent only a small part of the total number of times a work has been read due to the fact that they come only from registered users.

This set comprised the users that had read the largest amount of works. No filters were put in the works beyond the fact that they had to appear in the three datasets and as such they need to have been read by at least three users. These three files can be found in the [data](https://github.com/mmarcet/master_project_Kschool/tree/master/data) folder.
