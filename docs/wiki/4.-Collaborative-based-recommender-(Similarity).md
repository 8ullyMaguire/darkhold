This recommender will search for users that have read similar works to the user of interest and will recommend those works that are not shared between them. The similarity will be based on the cosine similarity due to the fact that the results it returns are compressed between 0 and 1, unlike other distances such as the euclidean distance, it is fast, unlike the manhattan distance, and can be run in sklearn with sparse matrices, unlike the jaccard similarity. Once the similarities between a user and all the others are calculated the script will select the N closest users and check which works they have read. Then it will weight the works read by each user by their similarity to the user of interest and then it will compute which items have the highest scores among the set of users. The ones with the highest scores will be the ones the script will recommend.

The order of the recommendation will be based on the similarity between users. So item 1 is recommended because the three most similar users have read the item. Item number 2 has been read by closest user 2 and closest user 3 and if the sum of similarities between those two users is bigger than the similarity of closest user 1 then this item will be recommended in second position. Item 3 is recommended in that positions because it has been read by the most similar user and so on.

## How to run the script

To perform this recommendation you will need to execute the following command:

`python3 ./4_collaborative_similarity/similarity_recommender.py -t train.u2i.txt -o recom.txt -k 50`

Where -t indicates the user to item table and -o indicates the name of the output file. -k establishes the maximum number of recommendations that need to be provided. The other options included in the script are:

* --minSimilarity: This is the minimum amount of similarity between two users needed for the user to be considered close. This will avoid the effect of taking random users when non is similar to the user of interest. 
* --num_users: This determines how many users will be considered close and as such contribute to the recommendations.
* --calcWholeMatrix: When calculating the similarity matrix this can be done in one setting or by user. The first option uses more RAM memory and as such should not be used when your dataset is too large. The by user option though is slower, so if possible this option should be used.
* --threads: When calcWholeMatrix is enable the similarity will be calculated in one single operation that can be multi-threaded. This option allows you to set the number of threads this process will use

## Test dataset

I used this script to make recommendations based on what similar users had read. I applied it on the training dataset, obtained the recommendations and then evaluated them using the evaluate script. I did that with different numbers of close users and different similarity thresholds to see how the results changed according to each variable.

The number of users will basically affect the order in which recommendations are made as something that is not recommended by the most similar users but read by many farther related users can end up being recommended. The more users you take as your close set of users the more likely that is to happen, although of course that will always depend on the similarity. We tested the recommender using 10, 25, 50, 100, 150, 200, 500 and 1000 close users. The best results were obtained when using 500 users with a f1@k of 0.0933 and a map@k of 0.0245. These results are better than the ones obtained with the non-personalized recommenders in which the best result was a f1@k of 0.0364 and a map@k of 0.0090.  

The similarity threshold does not seem to have any effect on the results unless it is set very high (0.5) in which case it is detrimental to the predictions. This basically says that for this dataset there is not a problem finding similar users. When applied to a dataset with users that have read less fics, this may have a bigger effect in the sense that it will limit the number of close users.
