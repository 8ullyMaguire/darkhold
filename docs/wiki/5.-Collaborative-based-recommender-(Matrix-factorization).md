
A different method of collaborative filtering is based on matrix factorization. Matrix factorization takes a matrix consisting of ratings between users and items they consumed and then tries to find two rectangular matrices of reduced dimensionality whose dot product is able to reproduce the original matrix. The objective of this is to try and capture general trends that are hidden in the more detailed matrix. Once the two latent factor matrices have been built the recommender can get the predicted ratings for a user by multiplying the factors of the user and the items. Recommendations will include the top scoring items after the product has been calculated and the items already read by the user have been extracted. The advantage of such methods is that predictions can be made of items that have not been read by similar users.

[Implicit](https://github.com/benfred/implicit) is a library designed to run matrix factorization on implicit data. It assumes that 0 means that the user did not like the item but balances that assumption by putting a confidence parameter that indicates how sure you are about your assumption. It is programmed in Cython to make it fast and it implements different algorithms for matrix factorization including Alternating Least Squares (ALS), Logistic Matrix Factorization (LMF) and Bayesian Personalized Ranking (BPR). There are several hyperparameters that can be optimized for matrix factorization algorithms. They include the number of latent factors, which in essence is the abstraction level applied on the initial matrix, the regularization parameter which is introduced to avoid overfitting, the number of iterations and the confidence value (alpha). In Logistic Matrix Factorization and Bayesian Personalized Ranking there is also the learning rate. The recommender based on implicit used here allows the search of hyperparameters with the option explore (-e) or allows the user to directly imput a set of hyperparameters. The explore function will result in sets of recommendations provided by different sets of hyperparameters and it will be up to the user to select which was the best recommender. This was done so that the program could be run at different times and in different computers but still provide a comprehensive dataset on which to base the hyperparameter selection.

## How to run the script

The run the implicit recommender:

`python3 ./5_collaborative_recommender_implicit/collaborative_recommender_implicit.py -t train.u2i.txt -o recom.txt -k 50`

Where -t is the user to item table, -o the outfile where recommendations will be printed and -k the total number of recommendations. Running it like this, it will use the ALS model with a set of chosen hyperparameters. It is recommended that you first explore the hyperparameter space to search for the best possible hyperparameters that best suit your dataset. For such purpose I implemented a random search that uses ranges of values to search the hyperparameter space. The result of such a search will not be the set of best parameters, rather for each set of parameters tested you will obtain a recommendation which you can later evaluate and so decide the hyperparameters you want to use. 

To run such a search you can execute this command:

`python3 ./5_collaborative_recommender_implicit/collaborative_recommender_implicit.py -t train.u2i.txt -o recom.txt -e -n 50`

Where the -e option indicates that the exploration mode has been enabled and the -n option indicates the number of exploratory runs the script will make.

Additional options include the -a alpha), -f (factors), -r (regularization), -l (learning_rate) and -m (model) options that will allow us to manually set the hyperparameters we want to use.

## Test dataset

### Alternating Least Squares (ALS)

To set the random space in which hyperparameters would be taken I first ran 400 searches with a combination of set parameters in which I only used ALS as the model. From this search we see that the best results are obtained when using a 500 factors, closely followed by 750, this means that likely the optimal number of factors can be placed between 500 and 750. Both the biggest alpha (55) and the biggest number of iterations (50) contributed to the best results, which means that in further explorations we can go for bigger alpha and iterations values. Although not shown in the graph, the regularization parameter did not have an obvious best value and best results can take any of the regularization parameters tested.

In this graph factors are shown by color, number of iterations by shape and alpha by size. For a more detailed exploration of this data refer to the dashboard.

I further searched for the best hyperparameters by performing a random search this time. I repeated the search 500 times, and found that the number of factors for the best prediction were 676, the alpha was 96, and the number of iterations were 90. The metrics for this prediction in the validation set were a f1@k of 0.2025, which is by far the best result we have gotten in any of the recommendations, the matching map@k is 0.0815. This value is not the best for map@k which has reached in our dataset to 0.0826. Still we will use f1@k to choose the hyperparameters to make the final recommendation.

### Logistic Matrix Factorization (LMF) and Bayesian Personalized Ranking (BPR)

I performed a second random search with 500 iterations for the BPR and LMF models, but I did not manage to get good hyperparameters for those models. The LMF model does not learn anything, staying only slightly above the level of random recommendation (f1@k of 0.0045). Looking at the following graphs it is obvious that the hyperparameter space we scanned is not right for this model and should be adjusted.
